## 4. Storage and security (F8–F11)

- [x] 4.1 Persistent storage. `library/storage/persistent-storage.ts` (`createPersistentStorage`, seven specs): asks `navigator.storage.persist()` once, skips it when already persistent, records `granted` / `denied` / `unsupported` (a refusal or a throw is a status, not an error) and lets the UI subscribe. One shared instance now serves the recordings store (which had its own copy) and the offline audio store. The audio store asks only when a file is kept (`write` of a pinned entry, `setPinned(true)`), never for an automatic cache write: Firefox shows a prompt for `persist()`, which a background cache write must not raise. Persistence is per origin, so one answer also covers the waveform peaks and prepared stems that share the origin's IndexedDB (they are regenerable, so they do not request it themselves; a deviation from the task's first wording). The Offline files screen adds a line, "This browser may clear offline files when it is short on space.", only when the answer was no; wording and placement are a proposal, say if they should change. Scenario `persistent-storage` (a storage manager that counts and refuses): nothing before a keep, one request on the first keep, none on the second, and the line on the Offline files screen; three runs. Also fixed a regression from 3.4 that the full unit run exposed: `useReduceMotion` called `subscription.remove()` on the undefined that react-native-web returns without `matchMedia`, failing `recordings-auto-export-section.spec`; full unit suite 3746 pass, 0 fail
- [x] 4.2 Token storage decided with the user: keep `localStorage` and rely on the CSP (4.3). The record is a roughly one-hour access token with no refresh token, saved with its expiry and scope under one key and dropped on expiry, so the exposure is short and moving it to `sessionStorage` or memory would only cost a reconnect on every launch without helping against a script already running on the page. No behaviour change; `authorization.spec.ts` gains a spec pinning that the record holds only `accessToken`, `expiresAt` and `scope` (the existing specs already cover restore, clearing, and the expired marker carrying no token). Revisit if 4.3 cannot reach a strict CSP
- [x] 4.3 Meta CSP. `public/index.html` carries `default-src 'self'; script-src 'self' blob: 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; media-src 'self' blob: data: https:; connect-src 'self' blob: data: https:; worker-src 'self' blob:; object-src 'none'; base-uri 'self'; form-action 'self'`. What it can and cannot do, from running the suite under it: the app has no inline script and no eval, so script is limited to its own origin; `blob:` is needed because the audio worklets (pitch shifting, pitch and recording microphone feeds, composite engine) load from blob URLs (the first draft without it broke the piano, pitch and recording scenarios), which a later change could remove by shipping the worklets as assets; `'unsafe-inline'` is needed for styles (react-native-web writes style attributes); `connect-src` and `media-src` allow any `https:` host because people add audio and score links from anywhere, so the policy limits script injection but does not stop a script that gets in from sending data out. Not covered: `frame-ancestors` (header only). The harness now fails any scenario on a CSP violation (`runScenario` checks `assertNoCspViolations`; a scenario can claim an intended one with `expectCspViolation`), and the new `content-security-policy` scenario proves an injected inline script, a string `eval` and an other-origin script are refused and do not run (Playwright's own `evaluate` is exempt from the eval check, so the eval is tried through a string timer). Default lane 69/69 and the Chromium matrix lane 4/4 under the policy (the matrix lane was run locally; WebKit and Firefox are for 6.3). Not checked: the Expo dev server (`expo start --web`) under the meta tag, and real Google sign-in
- [x] 4.4 `noopener` on external links: not needed, 1.2c passes
