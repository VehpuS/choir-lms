## 1. Native playback follow-ups

Moved here on 2026-10-12 from `nocturne-visual-system-and-playback-shaping` (group 8), so that change could be completed and archived. Web is the verification target for that change; these three items need a native decision or a device. Nothing here is scheduled: pick them up when native becomes a priority target, and write the design and spec deltas first.

- [ ] 1.1 (was 8.41) **Native waveform peaks (deferred by the user 2026-10-06 until native is prioritized as a target; see the native note under group 7).** Native shows the flat placeholder band for every item because it has no decoder (4.1). Options, from the 4.1 measurements: (a) a native decoder module such as `react-native-audio-api` (`decodeAudioData` on a downloaded file; needs a dev-client rebuild and a file download step, and its Expo 54 / RN 0.81 compatibility must be confirmed, which the sandbox could not check); (b) a JS-only partial MP3 decode that skips the expensive synthesis stage: walk frames, Huffman-decode and requantize the spectral coefficients, and take energy per granule as the envelope (the user's JS preference; MP3 only, and m4a / AAC, FLAC, and Ogg would stay flat); (c) extracting on the server, which does not exist. Needs a spike on (b)'s speed in Hermes before committing, and the user's decision on (a) versus (b).
- [ ] 1.2 (was 8.51) **Semitone pitch on native iOS and Android (deferred, deliberately not planned; reconfirmed by the user 2026-10-06).** Decided by the user (2026-10-02): web is the priority platform, so native pitch is skipped in this change and is implemented only if native becomes a priority; no task here should build toward it. What must hold meanwhile: the limitation is explicit in code (`canShapePitch`, 5.1) and the native UI shows the inert fallback with its reason (6.1, spec `playback-shaping`). If revived, options and costs are recorded under 5.0: Android needs RNTP to expose ExoPlayer pitch (patch or fork; no `patch-package` setup and no Android project directory today), iOS needs an `MTAudioProcessingTap` + SoundTouch or an `AVAudioEngine` / `AVAudioUnitTimePitch` module (the latter needs the file on disk, overlapping 8.37); both need on-device verification.
- [ ] 1.3 (was 8.44) **Peak storage budgets and eviction are untested on device (verify).** Web IndexedDB is budgeted at 64 MB (about 500 five-minute tracks) and native AsyncStorage at 3 MB (about 25); Android's database cap, per-row size limits, and iOS behavior were not exercised because native has no extractor yet. Re-check when 8.41 lands, including what happens at quota errors (today a failed write is swallowed and the peaks stay in memory only).
